Smooth Research · 启动包和待办

发件人只写几个字段，收件人读到的包由 CLI 从记录拼出来

通知只有一行，不存。待办（mailbox）是一次查询。启动包在读的时候生成，所以它永远和数据库一致。

2026-11-24 定，11-25 按第 43 至 48 项改 · 尚未实现 · 依据整合文档 7.7、8.11、11.2 和 11.5 · 消息的格式见消息设计页 · 范例里的编号和内容是示意

存哪

五样东西里只有两样要存

这一程发件人运行的命令发件人写下的东西收件人读到的
协调者 → 科学家rl task create --kind hypothesis，rl task release假设任务卡的五项，约 150 字符假设任务包，约 8,000 字符
科学家 → 研究者rl task dispatch一句说明，最多 300 字符。实验、说明、实验清单、授权文件在交接前已经是记录和文件任务包，约 4,500 字符
CLI → 协调者没有发件人：协调者运行 rl pack无恢复包，约 4,500 字符
科学家 → 审核者rl review request审核问题一句，定位，说明（结论审核不带说明）审核包，约 2,500 字符，不含代码
研究者 → 科学家rl task deliver一句结论、限制、定位、说明待办里的一项，带核验行

字符数是估计：恢复包和假设任务包的大小来自整合文档第 11 章，其余两个是按范例估的。

待办

待办是 rl inbox 的一次查询，每项最多四行

待办就是 mailbox。命令名不变，但它不再读消息表：它拿规则表去查记录状态。一项做完，记录状态一变，这一项就没有了，不需要确认，也没有游标。

命令谁用做什么
rl packagent打印调用它的会话的启动包。所有角色都用它，包括协调者
rl inboxagent查自己的待办；--item N 展开一项
rl resume用户把这个项目接着跑起来：确认 herdr 里有协调者的面板（没有就开一个，从启动包启动）、监视在运行；打印项目状态和等用户决定的事11-25 改
rl status用户只看项目状态、等用户决定的事和监视在不在运行，不启动任何东西。项目状态是研究页“现在”一节的短版，再加上次阶段报告以后新出的假设结论
rl view用户立即重画研究页；监视在运行时会自己重画11-25

用户不运行写命令：在协调者的面板里答复，协调者用 rl request answer --by user 记下。用户也在这个面板里问项目的事：协调者读记录和研究页来讲，问到代码、日志或审核讨论，就开一个只读子代理去读，只拿回答案和定位（整合文档 7.7）。交接的命令叫 rl task dispatch；旧的 rl task handoff 删掉了，不会再被打错。

机器重启或全部关掉以后，用户运行一次 rl resume，监视就按待办在新面板里把各个会话叫起来。监视每一拍写一次心跳；心跳过期时，任何 rl 命令和会话启动时的提示都提醒运行 rl resume。新版本不兼容旧项目：rl resume --role coordinator、rl context --purpose work、rl agent brief 都删掉，角色卡只写 rl pack（整合文档 10.4）。

结构

每个启动包都是同样的五块

协调者

恢复包：待办、排期和候选假设，没有代码

没有人给协调者“发”这个包。它的对话清掉重开、压缩或重启以后，协调者运行 rl pack，CLI 从记录生成。协调者的面板也是用户说话的地方，用户在的时候，监视不清掉它的对话（整合文档 7.7）。下面是 T-0040 刚交付时的样子。

科学家

假设任务包：协调者只写了卡上的五项

研究者

任务包：授权全文放进去，实验不抄

审核和顾问

审核包不带作者的说法，结论审核连说明也不带

包本次的卡必要材料不放
拆树（科学家）拆树任务卡：计划的编号、约束、要交回的东西计划全文，只有这个包放；换方向时再加现有的树、已有的决定和换方向的原因代码、运行、日志
短会话（科学家）阶段结论任务卡：阶段和它包含的任务；或交给它的公共准备任务的卡：要求、done_check、阻塞原因阶段结论：阶段里假设任务的结论、决定和用量，假设树每个假设一行。公共准备任务：它的 Attempt 和开放的审核回合日志、交接文档
设计审核审核单：问题、被审的提交和文件、所属任务、第几次说明的编号、实验清单、受保护范围、语义测试；代码直接读仓库假设树、项目状态
复查审核单，指向上一次审核上一轮的发现和它们的状态；修复的 diff和设计审核相同
结论审核审核单：问题、决定草稿封存的预测、判定函数的修订、引用的证据、核验行作者的说明和推理
顾问咨询顾问单：一句瓶颈问题相关的假设链、已试的路径和结果、约束、最近的文献任务流水、代码细节
顾问裁决顾问单，指向升级的审核回合每条未关闭的发现；审核者和科学家在回合里的说法；引用的证据回合以外的讨论

唤醒

续用只读一项，清掉重开才读整个包

每个会话开在 herdr 的一个面板里，审核者和顾问也是。监视往面板里提交一行提醒（herdr agent prompt）；还没有会话时，开一个面板启动 agent（herdr agent start）。往协调者的面板里提交要等它空闲、用户几分钟没说话，否则先等着，发一条 herdr 通知（整合文档 7.7）。没有 herdr 时，rl resume 和监视拒绝启动（11.2，11-25 改）。

决定

这些在 11-24 定下，11-25 又改了几项

编号问题决定
24命令名rl pack 只给 agent：任何会话运行它，读到自己的启动包。rl resume 给用户：把项目接着跑起来，拉起监视，打印项目状态和等用户决定的事。rl inbox 查待办，--item N 展开一项（11-25：rl resume 也确认 herdr 里有协调者的面板；用户还有 rl view，第 43、46 项）
25各包的预算协调者约 4,500 字符，科学家约 8,000，研究者约 4,500，审核者约 2,500（不含代码）。角色卡、本次的卡和待办不裁，必要材料先裁最旧的
26科学家的包里假设树给多少全给，每个假设一行。超过约 150 个假设时，只给祖先链、兄弟、前提和以它为前提的假设，其余用 rl tree 取
27协调者的包里放不放假设树不放。只放排期、候选假设和最近接收的两个假设任务，整棵树按 id 取
28研究者的包里放不放假设不放假设树和命题，只放实验的问题和所属的假设任务编号
29授权文件和简要说明哪个放全文授权文件放全文，简要说明只给编号。授权每一步都要对照，说明读一次就够
30续用时发不发整个包不发。续用只发一行通知，会话读待办里的这一项；新开和压缩之后才读整个包（11-25：新开就是清掉对话再读启动包，第 47 项）
31作业结束怎么通知执行器用 command 方式运行一条 rl 命令，在 Attempt 上记下作业结束；提交者的待办里出现“作业结束”，监视叫醒它。研究者的包里不再写通知目标
32、33短会话挂在哪阶段结论用任务类型 phase；公共准备任务的阻塞和升级由协调者交给一个短的科学家会话。两种短会话的包见上表
34用户怎么答复在协调者的交互会话里答复，协调者用 rl request answer --by user 记下。阶段报告不挡下一阶段（11-25 改：用户在协调者的面板里说话，用户不在时也不再由无头对话接手，第 45、46 项）
37停止条件写在哪只写在实验清单的 stop_when 里，随设计提交封存。任务卡显示它，授权文件不写
39交接的命令名rl task dispatch，和旧流程的 rl task handoff（换人）分开（11-25：rl task handoff 删掉，第 48 项）
40监视停了谁知道监视每一拍写心跳。心跳过期时，任何 rl 命令和会话启动时的提示都提醒运行 rl resume；rl status 显示监视在不在运行
43研究页谁写，什么时候生成页由记录生成，字由知道的角色在写记录时写，协调者不写；阶段报告是页上这一阶段的一节。写命令不碰页面，监视在最新的 Event 编号变了时重画，rl view 立即重画；页面放在 docs/research.html，不进 git。rl status 打印“现在”和“等你决定”的短版，再加上次阶段报告以后新出的假设结论
45谁给用户讲解协调者兼任，不另设角色。代码、日志、审核讨论由只读子代理去读，只拿回答案和定位，这一条写进了角色卡。监视只在协调者空闲、用户几分钟没说话时往它的面板里提交提醒
46唤醒的后端只用 herdr：每个会话开在一个面板里，审核者和顾问也是；没有 herdr 时拒绝启动；无头方式和协调者锁去掉
47醒来比空等贵用清掉重开，不用主动压缩：空闲超过缓存时间、上下文又大时，监视在提醒之前清掉对话，让它读启动包；不在每轮结束时清；用户在时不清协调者的对话
48旧项目这次重新设计不兼容之前的项目：新版本只建新项目，schema 5 之前的数据库一律拒绝；只限这一次，升级机制保留。rl resume --role coordinator、rl context --purpose work、rl agent brief 和 rl task handoff 都删掉，角色卡只写 rl pack

第 24 至 30 项是整合文档第 14 章原来的编号；第 31 至 40 项是复查时提出的，记在 14.1 节；第 43 至 48 项在 11-25 定下，记在 14.3 节，这里列出和启动包有关的五项（第 44 项去掉论文草稿，和启动包无关）。它们都记在第 13 章。范例用中文写，是为了方便核对内容；实际的包和现在的 CLI 输出一样是英文。

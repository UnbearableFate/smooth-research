smooth-research · 设计总览

插件只记录，不执行

它把研究计划变成可检验的假说，用成本逐级增加的实验积累证据，把每次运行的事实登记进 LatticeDB。启动、轮询和取消实验，都由 agent 用自己的执行工具完成。

v0.1.0 · 记录格式 4 · 设计文档 v0.2 · 实施记录 §21.1–§21.24 · 248 项测试 · 2026-11-06

研究循环

每个结果都要指向下一步

插件不规定研究路线。它要求每个实验在运行前写下哪个结果导致哪一步，结果出来后再决定继续、收窄、诊断还是咨询。

图模型

关系绑定到具体版本，状态分维记录

六类核心对象（假说、任务、实验、证据、决策、论文）和辅助记录在同一个 LatticeDB 0.15.0 库里。tests、supports、challenges、based_on 都指向目标的某一版，例如 H-0001@1，而不是一个会变的文件路径。

运行记录

只登记事实，从不控制执行

register、record、import-result 三条写命令共用一个 store 入口，每次写入是一个事务。它们不启动、不查询、不重试；request_id 让调用方可以放心重试。

团队与审查

四个角色各在自己的会话里，经记录交接

现在有四个 agent 角色：协调者、研究者、审查者和顾问。协调者掌握路线和结论，实现与运行交给研究者。它们不在聊天里互相转述，而是经 rl 记录交接。在 herdr 里，其他三个角色各开一个 tab，研究者在自己的 git worktree 里工作，headless 命令拒绝执行；新 session 用 rl resume 接续。

会话监视

协调者不轮询：监视程序每 5 分钟看一遍会话

rl agent open 同时在 sr-watch tab 里启动监视程序。每一拍它经 herdr 看每个会话和协调者，Codex 会话再读日志新写的部分；发现汇成一条来自 watch 的 NOTE。它只往会话里输入固定的提示，从不连执行器。

计算资源

作业 MCP 走资源自己的连接，接口只有提交参数和导出

pi-env-mcp 只管传输，miyabi-mcp 管 PBS 语义，smooth-research 只管记录。作业 MCP 经资源的 connect 访问：connect: pi-env-mcp:miyabi-g 时，pi-env-mcp 在主机上运行 miyabi-mcp。miyabi-mcp 的导出直接交给 rl run record；一批作业共用一个通知组。

端到端测试

Miyabi 上三轮研究都走完了循环，联合测试纠正了作业 MCP 的接法

bf16 测试由 Claude Code 2.1.314（Sonnet 5.5）在 Miyabi-G 的 debug-mig 上完成，3 个作业的记录与台账逐字节一致，结论只到 screening。联合测试让 Claude Code 和 Codex 互换协调者与角色，各跑一轮（A、B），改正接法后各重测一次作业路径（A′、B′）。

项目配置

程序只读一个文件，写错了也不让命令失败

配置分四处：项目根目录的 smooth-research.yaml、约束文档 docs/constraints.md、几个环境变量和命令行选项。CLI 只读 smooth-research.yaml；约束文档写给人和 agent，CLI 不执行它。默认值在 project.py 的 DEFAULT_CONFIG，详细说明在 docs/configuration.md。

实现

一个共享核心，两个宿主薄适配

核心与 CLI 在 src/smooth_research/，插件公共部分在 plugin/；hosts/ 只放 manifest、hook、宿主说明和占位符取值。没有 MCP 包装：CLI 已覆盖两个宿主。

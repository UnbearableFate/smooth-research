审核

一个回合一个会话，谁请求谁启动

rl review request 一条命令建审核单并启动会话。模型由 CLI 按配置选，请求者不能指定。每个任务同一时间最多一个开放回合，所以不需要排队和上限。

问题决定
谁启动审核会话谁请求审核，谁启动；一个回合一个会话（图 6）
协调者怎么验收任务结论读 CLI 生成的核验行，必要时抽查证据
自由消息协调者到其他角色、研究者和审核者之间可以自由发；发给协调者的只有固定类型和格式（图 5）
贵运行要回协调者吗任务卡授权内不用回；超出授权就发阻塞
怎么回答协调者的自由提问固定类型“答复”：引用那条消息的 id，每条最多答复一次

落到代码：rl task deliver 从账本生成核验行，包括运行状态、证据 id、审核是否通过、branch head 是否等于通过测试的 commit（verification_lines 现在只做最后一项）。rl agent tell 和 rl msg 拒绝会话发给协调者的消息。_reviewer_brief 和 _advisor_brief 去掉 tell coordinator 的步骤，由 rl review answer 和 rl advise answer 发固定消息。

## (a) Blocking

1. **A relocated backup can resume work in the original project.** I restored a dispatched task into a sibling clone and recreated its task worktree at the same commit. The next watcher beat passed the **original** worktree as both the researcher's working directory and `SMOOTH_RESEARCH_CHECKOUT`, alongside the **restored** database as `SMOOTH_RESEARCH_PROJECT`. A file written in that session directory appeared only in the original tree. This occurs when resuming an already-claimed task at a new location, even with the correct worktree ready. Resolve the task checkout from the active project and task ID when opening the session. If that checkout is missing, report which one to recreate. `tasks.py:152–155`, `snapshot.py:82–85`, `watch.py:148–154,183–193`, `launch.py:160–165`

2. **A nested project cannot start its job from the generated archive.** I ran the staging block from `rl compute steps --attempt` for a registered cluster attempt using `connect: local`. With the project at `examples/project`, Git archived that subdirectory's contents at the snapshot root and omitted a shared file at the repository root. The printed job directory, `snapshots/<commit>/examples/project`, did not exist. Repeating the command reported “already staged”. A repository-root project staged correctly, and archiving the same commit from the worktree's Git top preserved both files at the expected paths. This is deterministic for the nested layout on shared storage. Generate archive commands from the repository top and check the expected project directory before reusing a snapshot. `compute.py:151–160,246–259,284–295,316–319`

## (b) Worth fixing

1. **Doctor misses changes to artifacts imported from the researcher's normal working directory.** The caller checkout and the task worktree resolve to the same file. Import records the first match as `checkout`, and doctor then reads the main project's path. With a task-only file, changing it left doctor clean from both directories. With an older main copy, doctor flagged the freshly verified result before the task file had changed. This affects the documented local workflow before merge. Record the task origin when the two candidates identify the same file, and resolve it through the same project-relative logic in doctor. `runs.py:514–525,537–548`, `snapshot.py:118–132`. [Local researcher workflow](../../../plugin/skills/smooth-research/references/workflow.md#a-local-run-end-to-end-a-researcher-in-its-worktree)

2. **The documented local accounting command charges local work.** Following the workflow's `local:<host>:<attempt>` example on a two-run local task made its check and the project summary report 42 CPU-seconds used. The count of excluded local attempts fell from two to one. A charge above the hypothesis allowance also raised a coordinator budget notice. Agents following that example can therefore produce incorrect spend figures. Apply the local-attempt rule when aggregating accounting records in both views, preserve shared remote charges once, and replace the local example. `usage_view.py:38–55`, `runs.py:727–742`. [Usage instructions](../../../plugin/skills/smooth-research/references/workflow.md#usage)

3. **Normal executor imports can cross a budget threshold silently.** The Miyabi export fixture recorded 0.171389 node-hours against an initial 0.2 node-hour allowance. The 80% line was crossed, but the scientist received no notice. With a previously adjusted 0.1 allowance, neither the scientist nor the coordinator saw the 150% notice. A manual accounting revision immediately produced the expected notices. The export writes a Usage record and a `run.record` event, while the inbox dates spending from project-wide `run.usage` events. This affects the standard cluster import path. Derive the latest charge from the current accounting records covering the hypothesis, or emit the same scoped event from both writers. `runs.py:473–476,718–723`, `inbox.py:536–558`

4. **Copying the printed staging or sync block can report failure after success.** The shell requires the heredoc's closing `SR_EOF` at column one. The renderer indents it. A verbatim shared-storage block staged the snapshot, then exited 127. The SSH sync block fetched the candidate and printed “ready”, then exited 127 on both attempts. Removing the display indentation made the same sync block exit zero. This is recoverable for a person and disruptive for an agent that relies on command status. Emit a directly executable block with the delimiter at column one. `compute.py:232–243,550–556`

## (c) Notes and validation

The declined round-ten cases remain closed under the project's stated release policy. The architecture would benefit most from sharing two decisions currently made independently: which worktree belongs to an active project and which accounting records contribute to a task's spend.

**128 repository tests passed**, along with Pyflakes and Ruff's `E9,F401,F63,F7,F82` checks. The 52 disposable cases exercised CLI role flows, Git clones and worktrees, snapshot relocation, executor exports and the rendered shell blocks. Herdr and SSH transport used local fixtures. This review did not run live Codex roles or submit a cluster job.

The most valuable permanent tests would launch a restored task and assert its actual working directory, import a task artifact from that directory and audit it from main, and run the generated staging block unchanged for a nested project. For accounting, test both a local charge supplied through the documented CLI and a threshold crossed through an executor export.

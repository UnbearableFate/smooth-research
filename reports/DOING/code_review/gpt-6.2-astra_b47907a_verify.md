## A · First local trial

**A1 · High · A test can credit an editable draft whose manifest it never ran.** I started a local semantic test on a reviewed draft selecting `k=19`. While its subprocess was running, a second CLI invocation switched the draft to `k=1`. The test read the task's selected manifest and printed `k=1`. Its pass was stored under the original `k=19` key. Restoring the original selection made the identical command fail independently, yet dispatch succeeded and an evidence run registered with `k=19`. This used one execute task, a clean worktree and ordinary CLI operations. The command and key share a database read, but the subprocess can read the mutable draft later. For the trial, serialize draft edits and tests. For a durable fix, give the test an immutable design snapshot or increment a draft edit counter on every change and check it in the result write. `tasks.py:254–260,312–329,412–418`, `research.py:253–267`

## B · Before job-mode or remote use

1. **High · Job result ordering compares timestamp strings.** A pass observed at `19:00+09:00` cleared a failure at `10:01+00:00` on the same date. Dispatch also accepted when the failure was at `10:00+00:00`, exactly tied with the pass. Both observations were accepted by the executor-record interface. Compare parsed instants for both sorting and tie detection, including stored results. `runs.py:364–367,430`, `tasks.py:335–350`
2. **High · One successful attempt can accept a round whose retry is still running.** I registered two attempts of the same merge-test run. Recording the first success moved main while the retry was running. After an interruption between recording that success and applying it, the watcher made the same move through `finish_merge`. The retry then failed and the task stayed accepted. I also interleaved acceptance with registration's final write and obtained a prepared attempt for the already-accepted round. Use the same write-locked round check in every job-mode acceptance path, wait while any attempt is pending, and recheck the round when registering the attempt. `tasks.py:804–814,852–886`, `runs.py:70–77,140–152,173–184`
3. **High · A lost terminal notification leaves a merge waiting indefinitely.** After the public researcher registered the job and recorded it running, I advanced the inbox clock an hour past its deadline. The watcher produced no overdue item for the researcher. The private scientist case behaved the same way. The existing merge-test exclusion skips both ended-job handling and the overdue check. Apply that exclusion only to ended jobs so the submitter can recover a missing notification as specified in §6.5. `inbox.py:340–359`
4. **High for shared Git repositories · One project's watcher deletes another project's live candidate.** I initialized a second project with its own store in the same committed Git repository. Its empty set of pending tasks removed the first project's branch between repair and push. Sync reported success, but the bare origin lacked the registered candidate and the first task still waited for its job. Scope candidate names, enumeration and deletion to the owning project, or enforce exclusive repository ownership before touching refs. `tasks.py:775–795`, `gitops.py:201–219`, `compute.py:450–457`
5. **Medium · Failed ref deletion is reported as successful repair.** With a Git ref lock present, cancellation committed and repair returned true although the branch remained. The next sync pushed that cancelled candidate to a previously empty origin and reported no problems. Removing the lock allowed local repair to finish. A subsequent clean sync still left the cancelled ref on the origin. Propagate deletion errors, suppress candidate pushes after failed reconciliation, and retire published refs with an expected-tip check. `gitops.py:213–219`, `tasks.py:788–796`, `compute.py:450–457`

## Validation and test gaps

All **95 repository tests passed** in a detached checkout. An additional **33 disposable cases** exercised the CLI, store, Git, bare-origin pushes, watcher recovery and concurrent operations. The local workflow check used no compute resources, local tests and Claude-only role configuration with a fake Herdr. Live Claude sessions and a remote executor were outside this verification. Pyflakes and Ruff's `E9,F401,F63,F7,F82` checks passed.

The task's sealed design now owns test identity. The remaining duplication is in deciding which attempts belong to a round and when that round may accept. Reuse one predicate across registration, completion and recovery. The highest-value permanent regressions are the mid-test draft edit, equivalent instants with different offsets, a running retry during watcher recovery, a missed public merge-job notification, and ref reconciliation against a second project or a locked ref.

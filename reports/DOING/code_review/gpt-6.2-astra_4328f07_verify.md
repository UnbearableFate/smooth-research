## A · Local-trial blockers and the conditions that trigger them

1. **High · Re-import discards fresh evidence of conflicting files.** I imported a missing relative artifact, then placed different files at that path in the main and task checkouts. Importing the same manifest under a fresh request ID computed the ambiguity but returned the old usable result. `rl evidence add` accepted it. The reverse also reproduced: after resolving conflicting copies, a fresh import kept the result unusable. Changing only the artifact's role forced the correct verdict on the same bytes. Manifest deduplication predates this fix and now bypasses its ambiguity check. Preserve same-request replay and record changed verification on a fresh request, including the effect on evidence that uses the result. `runs.py:612–637`, `research.py:296–303`

2. **High · Doctor can audit the wrong project after restore.** I exported a verified relative artifact, restored to a sibling directory, and changed the restored copy. Doctor reported it clean. Restoring those bytes and changing only the original made doctor flag the restored result. This reproduced with both project and task origins. The new absolute `local_file` survives restore verbatim. Older results have the complementary gap: an actual `e3d653f` task-only artifact could change with no finding because its record lacks `local_file`. Resolve relative artifact origins against the project being audited and consult its task worktree for historical records. Keep absolute manifest paths explicit. `runs.py:538–548`, `snapshot.py:78–85,118–126`

3. **Medium · A restored project needs Git to import an existing relative file.** In a fresh `rl restore --into` destination with the artifact present, both a new import and an exact replay failed with the task-branches Git-repository error. An absolute path to the same file succeeded. The new task-location lookup requires a Git commit before checking any candidates, and runs before the request lookup. Check for a recorded request first and treat an unavailable task worktree as an absent candidate. `runs.py:510–526,612–620`, `gitops.py:35–43,61–73`

4. **Medium · A revised execute task can leave both recipients waiting.** A scientist received the first conclusion, returned it and received no prompt for the revised conclusion. On a second return, the researcher likewise received no prompt for the new correction. Both inboxes contained the updated text. Their delivery and return items reuse the first notice key until the reminder, four hours by default. Apply the task revision to these notices as the coordinator path now does. `inbox.py:44–51,227–249,421–425`, `watch.py:295–300`, `project.py:62`

5. **Medium · Session cleanup can leave a live agent or a stale user decision.** After tree acceptance, one timeout in either tab lookup or tab close made the watcher record the scientist session as closed. Its tab and agent survived two further beats. Keep cleanup pending after an inconclusive response and retry. Separately, with two historical open coordinator rows, answering the live pane cleared only its row. The older row's stale dialog stayed in the user inbox through resume and two beats. Reconcile superseded rows under the write lock without closing the live tab, and use the same current row when building the inbox. `watch.py:247–286,369–383`, `cli.py:475–495`, `inbox.py:576–582`

6. **Medium · A JSON type change can pass the exact-config check.** An allowed setting registered as `{"mode":[true]}` and reported as `{"mode":[1]}` produced `spec_match=true` and a usable result. Evidence registration accepted it. Python container equality equates these nested values. Compare JSON values with their types preserved. Also correct the registration step in the researcher card, which still reserves `--config` for deviations even though the import step correctly describes allowed overrides. `runs.py:126–139,581–590`, `util.py:55–59`, `cards.py:92–101`

## Architecture, regression coverage and verdict

The inbox's single index for review order resolves the measured repeated reads. Session recovery still has three consumers choosing a current row independently. A shared selection rule would remove that duplication. Artifact import and doctor likewise need one definition of where a recorded file belongs, with the immutable manifest and subsequent observations of local bytes represented separately.

All **127 repository tests passed**. Pyflakes and Ruff's `E9,F401,F63,F7,F82` checks passed. Disposable CLI tests exercised real Git repositories, historical stores, independent sync processes and the local flow through sign-off. Herdr, the scheduler and SSH transport were simulated. The highest-value permanent regressions are fresh-request re-import after files appear, export/restore while the original remains accessible, repeated execute-task corrections, answered duplicate sessions, a timeout during closure, nested JSON type changes, and a fresh worker clone using an explicit SSH URI.

The ordinary local trial can proceed with manual observation. Evidence acceptance after re-import, integrity checks on restored projects, and unattended correction delivery still need fixes before relying on those paths. Remote workers requiring a named SSH account need the clone fix before rollout.

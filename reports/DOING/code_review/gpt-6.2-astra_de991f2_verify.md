## (a) Local-trial blockers

**High · A result that explicitly identifies another attempt or run specification can become confirmatory evidence.** The trigger is selecting a previous output file when importing a repeat with the same arm, seed, commit and config. I ran two registrations with different environment parameters. Both wrote the attempt ID and spec digest supplied by `rl compute steps`. On the first import, I paired the earlier file with the later attempt. The stored result named the later attempt, its manifest named the earlier one, and the CLI set `spec_match=true`. `rl evidence add --level confirmatory` accepted it. Separate controls showed that either identifier can disagree on its own and that matching identifiers work. This affects both local repeats and downloaded cluster results. Compare supplied `attempt_id` and `spec_digest` with the selected attempt and its Run before granting evidence eligibility. `compute.py:193–196,222–226,328–330`, `runs.py:562–591,621–639`, `research.py:296–312`

## (b) Job-mode and remote blockers

**High · Switching a local trial to the documented login-node configuration can execute tests on Miyabi's login host.** The workflow guide's YAML sets `compute.coordinator: login` and a scheduler resource but omits `compute.tests`. The effective default is `local`. In an isolated project using that configuration, `rl compute` said to submit tests, yet `rl task test` executed a harmless working-directory probe directly and recorded a pass. Delivering a public preparation task also executed its check locally twice, once on delivery and once on merge, without a separate test command from the user. **Setting `compute.tests: job` prevented both paths** and the job-mode trial completed with that setting. Make login policy select job tests or refuse the conflicting configuration before executing a check. The configuration reference already shows both settings. `project.py:65,336–339`, `tasks.py:254–258,308–317,575–578,744–768`. ## (c) Other findings

1. **Medium · Documented unit names can suppress Miyabi budget notices.** With the same 0.171389 node-hour export, a 0.2 allowance triggered the 80% notice under `node_hours` and stayed silent under either `node·h` or the workflow example's `node_h`. Five recorded Miyabi MIG drills showed the same distinction: 0.046944 against 0.05 triggered under `mig_instance_hours` and stayed silent under the suggested `MIG·h`. The spend is visible in the check, but allowance comparisons use exact strings. Use executor unit names consistently in examples and normalize the documented equivalent spellings for comparisons, while keeping distinct resource units separate. `research.py:30`, `tasks.py:91–93`, `usage_view.py:14–19,98–105`. [Usage example](../../../plugin/skills/smooth-research/references/workflow.md#usage)

2. **Medium · Later budget notices can be missed or reopened for unrelated work.** After an idle scientist received the 80% prompt, another charge took the same hypothesis past 100%. Its inbox showed 100%, but the next beat sent no prompt because both thresholds have the same notice key. In a separate run, the scientist addressed the warning with a route decision. A later charge for an unrelated public preparation task reopened the scientist's warning even though the hypothesis's spend was unchanged. Scope the charge history to attempts covered by that hypothesis and include the crossed threshold in the watcher's notice key. `inbox.py:44–51,536–558`, `watch.py:304–309`

3. **Medium on restore · Role packs still direct people to the original checkout.** After a researcher started in the correct restored worktree, I committed a change there and requested review. Both researcher and reviewer packs printed the original worktree. The reviewer pack named the new commit, which Git could resolve only in the restored repository. This can stall review after relocation even though session launch is fixed. Derive the displayed path from the current project and task ID, as `watch.folder` now does. `pack.py:135–143,235–237,289–294`, `watch.py:148–160`

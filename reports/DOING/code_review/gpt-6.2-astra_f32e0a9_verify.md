## Regressions introduced by the fixes

1. **High · Local acceptance can strand a merge already on main.** With main and the delivery diverged, I interrupted acceptance immediately after the real fast-forward and before the database commit. The task remained delivered, main already contained the merge, and retry exited with a branch-at-wrong-delivery conflict. Acceptance itself had advanced the task branch to the merge commit. The new head check prevents retry from reaching the ancestor recovery check. Persist the candidate and delivery generation before moving main, then reconcile that candidate on restart. `tasks.py:631–637,657–675`, `gitops.py:179–191`.

2. **High · A new job-mode acceptance replays an earlier failure.** After a failed merge-test job, I accepted the same unchanged delivery again. Before a new job was registered, one reconciliation pass selected the old failed attempt and returned the task to delivered. Also, an identical registration request that returned its original attempt while merging was rejected after successful acceptance, because the new state check precedes request replay. Associate jobs with an individual acceptance, and return a matching persisted request before applying new-registration guards. `tasks.py:645–649,714–724`, `runs.py:59–65,96–103`.

3. **High · Existing schema-5 runs lose config validation, replay and retry.** I registered an evidence run with the actual `79ed0d7` CLI while its arm required `k=1`. At `f32e0a9`, a late result reporting `k=99` became confirmatory evidence even with the original experiment still sealed. Its stored spec has no `design.arm`, so import skips config comparison. An identical registration replay and a fresh evidence retry both returned conflicts because the recomputed spec now includes the snapshot. Recover the historical design from pinned data where possible, mark unresolved provenance unverified, and preserve the original request and retry identities. Include already-imported results in the upgrade assessment. `schema.py:14–18`, `runs.py:89–103,128–135,480–487`, `store.py:267–277`.

4. **High · Answering a design blocker can resume evidence work on the superseded design.** I blocked a dispatched task for a design change, opened revision 2, then answered the blocker directing the researcher to use that revision. A new evidence run registered immediately against revision 1. The answer restores the active state while retaining the initial snapshot, and registration now consults that snapshot even while revision 2 is a draft. Require a reviewed, tested handoff of the replacement revision before resuming evidence registration after a design change. Keep existing runs pinned to their own revision. `tasks.py:420–432`, `research.py:258–267,360–365`, `runs.py:53–55,84–95`.

5. **High · Updating a live coordinator can leave two agents running.** I resumed a stored coordinator with the preceding build's tab label and agent name, both `coordinator`, and a matching live host session. The new lookup rejected the name, cleanup left its tab alive, and resume started a second coordinator. The database tracked only the new one. The earlier naming contract is at `79ed0d7:launch.py:118,135`.

6. **Medium · Distinct projects can still receive exactly the same new Herdr name.** The path contributes 16 bits after a six-character folder prefix. The actual helper mapped both `/tmp/project-196` and `/tmp/project-290` to `projecf75e-coordinator`. ## Architecture, coverage and validation

The graph transaction works well for the hypothesis revision check and claimant validation. The remaining acceptance failures share a narrower architectural problem. The delivery, the Git candidate and the asynchronous test attempt have separate identities, but completion reduces them to a task ID and a boolean. One persisted acceptance containing those identities would serve local testing, scheduler completion and restart recovery. A single test-result predicate and a single reader for the task's sealed design would also remove the discrepancies between enforcement and `rl show` or packs. The two unused review helpers identified in the original report have been removed.

The highest-priority gaps in the committed suite are a restart after a divergent-main fast-forward, a second acceptance while an earlier completion is in flight, a test-command edit while a submitted job is outstanding, and a populated pre-fix project with an evidence run and a live coordinator. Also preserve the null-config, design-blocker, namespace-collision, cross-envelope and unchanged-dialog cases above. Assert the mainline commit, persisted task/attempt state, evidence eligibility and alert recipient in these tests.

All **76 repository tests passed**, including all four named regression targets. I ran 27 additional disposable probes against the CLI, Git repositories and LatticeDB stores. They exercised both successful paths and the failure cases above, with controlled interleavings at the relevant read/write boundaries. Herdr lifecycle probes used a fake and the installed Herdr 0.9.5 response shape. Notification probes used the local Miyabi renderer. Compute verification covered instruction generation only. Live model assignment and cluster execution were outside these probes. CodeGraph supplied caller traces. Ruff 0.17.6 passed `E9,F821,F822,F823`. Its full configured run reported 79 diagnostics.

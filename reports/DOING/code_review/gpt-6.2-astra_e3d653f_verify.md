## A · Local-trial blockers and their conditions

1. **High · A transient tab lookup can close a live conversation.** With an open row whose pane ID was stale, lookup by agent name found the live coordinator. I made the first lookup of its tab time out. The ownership check interpreted the error as absence. Cleanup’s second lookup succeeded and closed that same live tab. Both resume and the watcher reproduced this. Propagate an inconclusive lookup and leave the conversation available for the next beat. `launch.py:139–148`, `watch.py:253–255,271–280,305–312,493–501`

   **Medium · Recovery can also leave two open rows.** I exercised the history produced by the previous “name taken” race, with an open original row and a newer failed row. After pane renumbering, resume reopened the failed row and left the original open. The watcher found the live pane, but `rl agent dialog coordinator` selected the older row and reported no open session. Rebind the existing open conversation under the write lock before considering an ended row. `watch.py:247–267,367,484`, `cli.py:475–481`

2. **Medium · Two state changes fail to wake their recipient.**

   - **Scientist settlement.** After the final failed review, the researcher registered a smoke trial while the finding was escalated. The scientist then withdrew the last finding. Evidence registration was now allowed, but the prior smoke attempt suppressed “go on”, and its running state also hid the task card. Compare registrations to the event that actually moved the round to `passed`, including `review.settled`. `reviews.py:346–365`, `inbox.py:296–306,330–340`
   - **Revised phase delivery.** The coordinator received the first report, returned the task and received no prompt when the scientist delivered the revision. The inbox contained the new request and correct command, but the watcher had marked the same task-based coordinator key as delivered. Include the report request ID or delivery revision in the coordinator’s notice key. The default reminder is four hours. `inbox.py:44–48,409–418`, `watch.py:290–295`, `project.py:62`

3. **High for evidence integrity · Artifact import and audit can read different files.** In a project nested under a Git repository, importing a task-only file from the main checkout reported it missing. Importing the same path from the task checkout verified its digest. The fallback uses the worktree root and drops the project subdirectory. Even in a repository-root project, changing a verified task-only file left `rl doctor` clean because it checked only the main checkout. Where both checkouts contained the relative path, an older main-checkout copy caused a valid task-file digest to be marked mismatched and the result unusable. Use `gitops.checkout_in` for the task location, retain which file supplied the digest for subsequent checks, and identify ambiguous matches when they disagree. `runs.py:506–534,607–616`, `gitops.py:67–73`, `snapshot.py:118–122`

4. **Medium · The card can tell the researcher to record a configuration it did not run.** An arm specified batch size 8 and explicitly allowed that parameter to vary. Registration accepted 32 without a deviation. Import marked both the faithful report of 32 and a report copying 8 from the card as usable. Tell the researcher to report the effective configuration actually run. Check that against the registration, while retaining the allowed-key exception when comparing the registration to the design. `cards.py:92–102`, `manifest.py:75–77`, `runs.py:558–567`. ## B · Job-mode and remote blockers

1. **High · Fetch credentials still appear in CLI output and can enter project history.** With a credential-bearing fetch URL and a clean local push destination, a successful `rl --json compute sync` exposed a synthetic credential in the clone command inside `summary`. `rl compute steps` exposed it too. With the URL in the resource’s `git_url`, it also appeared in `rl compute` and the researcher pack. A simulated repository creation persisted the marker in `compute.repository`. Keep authenticated URLs internal to transport and render a credential-free worker URL, resource description and event message. `compute.py:118–120,133,276–282,301–304,395–397,554–566`, `project.py:411–425`

2. **Medium · An unchanged historical test job cannot be retried under its run ID.** A design-test run registered by `298955e` under the explicit-null key failed at HEAD with “the spec differs” when retried with the same arguments. Starting a separate run worked, and the original attempt’s completed pass was accepted for dispatch. Apply the two recognized keys when comparing the nested test design for a retry of a never-edited experiment. Preserve the original RunSpec and digest. `runs.py:119–125,158–164,294–298`, `research.py:386–397`

## Architecture, test gaps and validation

The inbox and tree guard now agree on numeric review order. **A · Medium for long-running local trials.** Every passed design round re-queries and decodes all rounds of its task, including finished tasks that cannot emit a verdict. In a fixture with one completed task, 40 historical passes decoded 1,600 ticket rows in 0.39 seconds. Doubling the history decoded 6,400 in 1.57 seconds for the review rule alone. Compute the latest round per task and kind once from the tickets already loaded by `Rules`, retaining the same ordering as the command guard. `inbox.py:86,259,288–291`, `reviews.py:59–60,117–121`

All **119 repository tests passed**, as did Pyflakes and Ruff’s `E9,F401,F63,F7,F82` checks. **62 disposable cases** covered actual upgrade stores, CLI role flows, fake Herdr sessions, separate sync processes and real local Git destinations. The live all-Claude run is documented in the trial record. This verification used simulated agent and scheduler interactions.

The highest-value permanent tests are a transient tab error during rebind, settlement with an intervening smoke attempt, a returned and redelivered phase, import followed by doctor in a nested task checkout, an allowed configuration override, and credential checks against the complete sync result, pack and event history.

# Codex trial, 2026-11-25

This trial installed the plugin built from `redesign-v5` (at `0c3b2cd`) in Codex 0.172.0 with `codex plugin add smooth-research@smooth-research`. The same minimal project as the [all-Claude trial](all-claude-2026-11-25.md) then ran in a separate herdr workspace. All five roles were `codex:gpt-reserve@medium`, Codex's "fast and affordable agentic coding model". The plan made one claim: the mean of three N(5,1) draws has a smaller absolute error than one draw. The work was to stop after that hypothesis.

Result: H-0002 and H-0001 are **supported** in the simulated model. The mean of three draws had 0.532× (seed 0) and 0.623× (seed 1) the absolute error of a single draw. The expected value is 1/√3 ≈ 0.577, and with 300 repetitions per seed a difference of about ±0.05 is within noise. The scope is simulation only, with two seeds. Without the stalls, the run from the first prompt to the phase report took about 15 minutes. `rl doctor` found nothing.

## Problems found and fixed

1. **Nothing woke the scientist for the verdict.** After accepting T-0003, the scientist ended its turn, as its item asked. Its "test H-0002" item had already been told at the start, so it was not news again until the four-hour deadline. In the all-Claude trial, Haiku happened to go on to the verdict in the same turn. Now every task under a hypothesis task that ends makes that item news again, and once all of them have ended it asks for the next task or the verdict. Fixed in `d648ce7`.
2. **A review request was typed into a dialog and lost.** I had reinstalled the plugin to pick up fix 1, which marked its hook as modified. The next Codex session, the conclusion reviewer, opened at the hook review. herdr reports that dialog as idle, so the next beat cleared the session's dialog note and typed the request into the dialog. The request still counted as told. Now, for a host with such dialogs, the watcher reads the screen before it tells, and a dialog there waits for a decision just as a blocked one does. Fixed in `e69ccd1`. I reset the told record of that one session by hand so the request was sent again.
3. **Fix 2 mistook the coordinator for a session at a dialog.** The coordinator had read the scientists' hook dialogs, so their text appeared in its own transcript. That held every item for the coordinator and put a false "answer coordinator's dialog" in the user's inbox. A dialog now counts only in the last lines of the screen, and never while Codex shows the footer of its prompt box. Fixed in `61a224f`.

Fixes 2 and 3 were copied into the installed plugin (`rsync -c` from `dist/codex`) instead of reinstalling it, so the hook did not need trusting again.

## Observations, not changed

- The coordinator answered every later hook dialog with "continue without trusting", so the plugin's SessionStart hook did not run in those sessions. Their work did not suffer, because the watcher's first prompt points each session at `rl pack`. After any plugin update, a user who trusts the hook once avoids these dialogs.
- The phase scientist wrote the phase conclusion while T-0005, the composite parent's verdict, was still open. `rl status` then listed T-0005 under "conclusions since the last phase report". The order is allowed, and nothing was lost.
- The coordinator once wrote `T-1` for `T-0001` and corrected itself after the NOT_FOUND error.
- The reviewer passed both the tree and the conclusions with no findings, in under a minute each. The one finding, in the design review, was real: the arms did not differ.
- Each Codex session shows the warning "Running without the shared background server" because rl passes `-c` overrides. It is harmless.
